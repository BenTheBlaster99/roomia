0. HOW TO READ THIS
================================================================================

Roomia is two surfaces sharing one catalog and one image brain:

  A) PUBLIC PRODUCT (no login)
     Marketing + Quiz + Styles + Room Composer + 3D Studio.
     This is what a visitor, Sarah, or an investor clicks in 30 seconds.

  B) PRO DASHBOARD (login)
     Drive + restyle generate + stacked history.
     Same compose brain as public Composer (paint, lights, optional furniture).
     Extra: files stay. Upload once, restyle, looks stack under the original.

The unfair win right now is PHOTO QUALITY:
  - Composer / Dashboard restyle a REAL room photo (walls, lights, furniture).
    That path NEEDS SAM2 for click masks, then GPT Image 2 for the edit.
  - Studio turns a 3D layout into a photoreal still.
    That path is ONE GPT Image 2 call. No SAM2.

Catalog-perfect 3D is the Studio track. It is demo-good, not catalog-perfect.
Do not confuse “GLBs exist and presets load” with “every SKU matches the photo.”
Do not confuse a great Composer photo with Studio being catalog-perfect —
two different quality bars.

Branch vs production (read this before demoing)
-----------------------------------------------
  main / room-ia.com
    Public Composer restyle + Pro Drive restyle as of 16 Aug 2026.
    Dashboard generate there is still: tap the photo first, then pick furniture,

  feat/homepage-refresh (this checkout)

2. CATALOG + 3D STUDIO — WHAT IS WORKING
================================================================================

Catalog (Supabase furniture_items)
----------------------------------
- Live catalog loads in Studio, Composer, and Dashboard generate.
- Mock catalog is the fallback if the DB fetch fails.
- Product photos (image_url) drive Composer identity lock (the model copies
  the real piece, not a hallucination).
- GLBs (model_url) + width_m / depth_m / height_m drive Studio scale.
- InstantMesh batch: 30/30 generated, uploaded, junk test rows deleted.
- Lights hang from the ceiling in Studio (not sitting on the floor).
- Dragging a ceiling light: grab the fixture OR the gold disc on the floor.
- Wall snap: pieces dragged near a wall sit flush.
- Placeholders (not fake generic GLBs) for pieces without unique photos:
  Gilded / Zellige / Atlas, TV units, some wardrobes.
- Removed duplicates: Majlis, Majlis Bed, Breeze.
- Pure chair enlarged and used in bedroom presets (Reed/Pebble out of bedrooms).

Studio (/studio) — working product
---------------------------------
Entry gate:
  - Pick a curated preset from room_presets, OR create a blank room
    (W×L×H from /configure or gate “Créer le vôtre”).
  - Reprendre restores the last local save in THIS browser
    (lib/studio-design-storage.ts, /studio?saved=1). Not the cloud Drive.

Inside the room:
  - Place catalog furniture in real metres.
  - Rotate, duplicate, delete.
  - Wall-snap while dragging.
  - Ceiling lights hang + drag on a horizontal plane.
  - Catalog sidebar: search, category, material, price (DZD).
  - Mobile: 1-finger drag furniture, 2-finger camera.
  - Photoreal button: 1 GPT Image call (see 4B). No SAM2.

Presets
-------
- Generated by: npm run generate-presets:dump then npm run generate-presets
  (needs service role; can read furniture-3d-gen .env).
- Living rooms + bedrooms rebuilt after the GLB pass.
- Bedroom layout: bed on back wall, wardrobe flush on right wall, one Pure
  chair, nightstand beside bed.
- IDs change every regenerate. Do not hardcode preset UUIDs.

Studio quality — honest
-----------------------
DONE for a demo / investor walkthrough.
NOT catalog-perfect:
  - Some InstantMesh SKUs still have holes / weak sides (Dagger side-only
    photo, L-shape Coupé, Lils). Extra product photos would help.
  - Placeholder wardrobes / TV units / Gilded / Zellige / Atlas need unique
    photos before they deserve a GLB.
  - Pure can still read a bit small next to a sofa in some scenes.
  - Do NOT re-run InstantMesh --production / 1536px on the 12GB RTX 3060.
  - Do NOT redo Venus / Dagger / Lils / Aurora / Neptune / Saturn at
    “medium” if the original low/4-view/512 restore is what looks right.

Photoreal from Studio was smoke-tested on a living-room scene: layout lock
held, quality looked excellent. That is the 3D → photo path.

3. PHASE FOCUS — ROOM COMPOSER (PUBLIC, NO LOGIN)
================================================================================

This is Feature A. This is the wow. This is what people should feel in the
stomach when they see before/after.

URL: /room-composer
Login: none. Keep it that way. Do not hide this behind Dashboard signup.

What it is (restyle pass, still the public flow)
------------------------------------------------
Not “drop a sofa in a photo.”
A full interior restyle of the SAME room, SAME camera:

  1. Upload a real room photo
     Tips: good light, include walls + ceiling if you want paint or a
     chandelier, shoot roughly straight-on.

  2. PAINT — tap a color dot (warm plaster, sand, terracotta, sage,
     gallery white, charcoal, burgundy, ink). Then tap the wall in the photo.
     Tap the same dot again to undo.

  3. LIGHT — pick one: Chandelier / Pendant / Floor / Sconce.
     Then tap ceiling, floor, or wall. The model is told the fixture is ON
     (glow + new shadows). Tap the same type again to undo.
     The AI invents a photoreal fixture of that kind (no catalog-light carousel).

  4. FURNITURE — optional. PUBLIC COMPOSER is still pin-first:
     tap up to 3 existing pieces in the photo, THEN pick from the live catalog
     (tabs: All / Sofa / Chair / Light / Tables / Rug).
     Catalog product photos are sent as reference images so the output
     matches the real SKU (strict identity lock, except rugs/curtains which
     may adapt to the footprint).

  5. Generate 3 restyles (hardcoded num_variations: 3 on this page).
     Button enables as soon as you have paint OR a light OR at least one
     furniture pin. You do not need furniture.

Markers on the photo:
  - Paint = colored disc
  - Light = gold star
  - Furniture = numbered pins 1–3

Progress UI: Masking → Generating → Results (3 images, click to select,
double-click / Agrandir to zoom). Partial success is kept if 1–2 of 3
GPT calls fail.

Why this matters commercially
-----------------------------
A sofa swap looks like a filter.
A wall color + a lit chandelier + a catalog sofa looks like a redesigned
apartment. That is what makes a client or an investor say “the space
actually changed.”

4. PHASE FOCUS — PHOTO RENDERING ENGINE (THE BRAIN)
================================================================================

Two GPT Image 2 entry points. Same model. Different jobs.
Public Composer and Pro Dashboard Generate share 4A. Studio uses 4B.

-----------------------------------------------------------------------------
4A. COMPOSER ENGINE  —  POST /api/compose/room
-----------------------------------------------------------------------------

Job: edit a REAL photograph. Keep camera, windows, unmasked architecture.
Change only the masked regions: walls, lights, furniture.

N GPT Image calls per run, where N = num_variations clamped 1–4
(API default 3 if omitted). Never “one call per pin.”
All furniture + wall + light go into ONE masked edit per variation.
That is how we stay cheap and keep the results comparable.

Public Composer always sends N=3.
Dashboard on this branch sends N=1, 2, or 3 (user pick, default 1).

Pipeline, in order:

  1. Client sends:
       image_base64
       zones[]            (0–3 furniture pins: x, y, prompt, category,
                           fidelity, optional product photo as reference_base64,
                           optional auto_place)
       atmosphere.wall    (optional: prompt + x,y of the wall tap)
       atmosphere.lighting(optional: prompt, kind, x,y, optional fixture photo)
       num_variations     (optional, 1–4, default 3)

  2. MASKING (needs SAM2 on AI_BACKEND_URL, usually :8000 locally)
       POST {image, x, y}  header x-roomia-ai-key if AI_BACKEND_SECRET is set
       → grayscale mask per click.
       Furniture clicks: as-is.
       Wall click: mask dilated (~10px) so paint covers the wall, not a speck.
       Light click: mask dilated (~42px) so a chandelier/pendant has room to
       exist (SAM2 on a ceiling tap is otherwise a tiny blob).
       All masks unioned into one RGBA PNG: transparent = GPT may edit,
       opaque = keep. Feather ~8px when restyling, ~5px furniture-only.

  3. PROMPT (lib/render-prompt.ts → buildMultiZoneComposePrompt)
       Image 1 = the room photo.
       Extra images = catalog product photos (and optionally a lighting
       product photo — public Composer currently does not send one).
       If atmosphere is present, the prompt says this is a FULL INTERIOR
       RESTYLE: walls must look obviously painted; lights ON with believable
       glow and contact shadows; still the same room and camera.
       Furniture lines: map each product to the masked blob nearest its
       click. Strict identity lock vs placement-adaptive (rugs).
       auto_place=true: the click is only a hint. The model is told to put
       the piece in the designer-natural spot (sofa on the seating wall, rug
       under the group, coffee table in front of the sofa, etc.).
       Heuristic tap points live in lib/placement-hints.ts so SAM2 still
       gets an x,y. Styles (Sarah) will tighten this later — not wired yet.
       Variations only change ambient light slightly (warmer / cooler /
       softer). Products and wall color stay identical across looks.

  4. GPT Image 2  client.images.edit
       model: gpt-image-2
       quality: high
       output: jpeg, b64_json
       size: auto
       mask: the combined PNG
       images: room + product refs

  5. Stream NDJSON back to the UI
       progress → done { variations[], failed_count, warnings }
       If all N fail: error. If some fail: show what succeeded.

Dependencies:
  - OPENAI_API_KEY  (optional OPENAI_BASE_URL if you proxy)
  - AI_BACKEND_URL  → SAM2 FastAPI (localhost:8000 locally, or the
    Cloudflare tunnel URL when generating from another PC / Vercel)
  - AI_BACKEND_SECRET → header x-roomia-ai-key (must match the GPU .env)
  - If SAM2 is down: Composer / Dashboard generate cannot mask. Error tells
    you to start the backend. GPT Image alone is not enough for restyle.

Identity lock (why catalog photos matter)
-----------------------------------------
Without a product photo, GPT invents “a beige sofa.”
With a product photo as image 2, 3, … it is told: same model, materials,
colors; only perspective / scale / lighting may change.
That is the difference between a pretty fake and “that is our SKU.”

-----------------------------------------------------------------------------
4B. STUDIO PHOTOREAL  —  POST /api/render/photorealistic
-----------------------------------------------------------------------------

Job: a 3D screenshot is NOT a photo. This call turns ONE Studio capture
into ONE photoreal interior photograph.

Always 1 GPT Image call per generate (not 3). Layout lock is the whole
point: same furniture, same positions, same camera. Allowed: materials,
lighting, shadows, photographic detail. Forbidden: moving/adding/removing
furniture or changing the camera.

Prompt includes floor material, wall color, room type from the studio
scene, plus a hard negative list (cartoon, CGI, floor grid, extra
furniture, different camera…).

Smoke-test (14 Aug 2026): living-room Studio render looked locked and
high quality. This path is investor-ready as a “we designed it in 3D,
here is the photo” closer.

No SAM2 on this path. The input is already the full frame.
response_format: b64_json is requested; extractImageBase64 also accepts a
gateway that returns a url instead.

9. ONE-PARAGRAPH TRUTH FOR AN INVESTOR
================================================================================

Roomia lets someone photograph a real room and restyle it — paint, lighting,
catalog furniture — into photoreal options without an account. The same
catalog lives in a 3D studio in real metres; one click turns that layout into
a photograph that keeps the furniture where you placed it. Pros can log into
a Drive, run the same restyle, and keep every look stacked under the original.
The public wow path stays free and no-login. Live generate still depends on
a GPU SAM2 box being on; Studio photoreal does not.
